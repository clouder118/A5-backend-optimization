# 数字人形象管理 PRD

- 状态：已确认，可进入开发
- 任务类型：本地 Markdown
- 就绪标签：`ready-for-agent`
- 产品范围：A5 灵山胜境 AI 数字人导览管理台

## 问题陈述

当前项目的 Unity WebGL 数字人资源随前端代码固定发布。管理员无法在管理台查看当前形象、导入新的 Unity WebGL 构建包、预览候选形象或切换当前形象。每次替换都需要开发人员手工覆盖资源并重新调整配置，既不适合实际管理，也无法在演示中体现“数字人形象可管理、可替换”的产品能力。

项目现有数字人不是单一模型文件，而是一组 Unity WebGL 构建资源，核心包括 Loader、Data、Framework 和 Wasm 文件，并依赖既有的 `Avatar151Bridge` 与前端传递欢迎、空闲、思考、讲解、口型和表情状态。因此，本功能需要管理完整的 Unity WebGL ZIP 构建包，而不是上传 FBX、VRM 或 Unity 工程后在服务器重新构建。

## 解决方案

在管理台新增独立的“数字人形象管理”栏目，提供紧凑的当前形象卡片、Unity WebGL ZIP 上传入口和版本列表。

管理员上传 ZIP 后，系统执行大小、安全性和 Unity WebGL 结构校验，将成功导入的资源保存为本地候选版本。候选版本可在管理台弹窗中预览，之后由管理员明确执行“设为当前”。启用后，新打开或刷新的游客端首页和 `/guide` 使用新版本；已打开页面不进行热切换。

项目现有 151 数字人作为不可删除的内置默认版本。上传、配置或运行失败时继续使用内置版本，确保数字人导览主流程稳定。游客端页面布局、交互、文案、聊天头像和其他业务功能保持不变，只调整数字人运行配置的解析与加载方式。

## 实施决策

### 领域与持久化

- 新增“数字人版本”领域记录，至少包含版本 ID、名称、备注、来源文件名、解压资源大小、内置标记、当前状态、上传管理员、上传时间、最后修改时间和最近启用时间。
- SQLite 只保存元数据和相对资源定位信息，不保存 ZIP 或 WebGL 二进制内容。
- 解压资源存放在当前后端本地数据目录的专用子目录中，每个上传版本使用不可变版本 ID 隔离。
- 内置 151 数字人以系统记录形式暴露，初始为当前版本、只读、不可删除；其现有前端资源不搬迁。
- 同一时刻只能存在一个“当前”版本。切换操作必须在数据库事务中原子更新。
- 名称不要求唯一；系统以版本 ID 区分构建。

### Unity WebGL ZIP 导入器

- 建立独立、可单元测试的 ZIP 导入器，统一负责限额检查、安全扫描、结构识别、解压、资源清单生成和失败清理。
- 上传 ZIP 最大 100 MB，所有解压条目的声明和实际总大小均不得超过 300 MB。
- 禁止绝对路径、父目录跳转、符号链接、设备文件、嵌套归档、系统可执行文件及其他不在允许清单中的危险内容。
- ZIP 可以直接以 Unity 导出目录为根，也可以有一层任意包装目录。
- 只允许识别一套构建：恰好一个 Loader、一个 Data、一个 Framework 和一个 Wasm 资源；允许文件名前缀不同。
- 支持未压缩文件及 `.gz`、`.br` 变体。导入器记录每个资源的媒体类型和内容编码。
- 支持可选 `StreamingAssets` 目录和可选 `fallback.png`。
- 导入过程先写入临时目录；全部校验成功后再原子移动到正式版本目录。
- 任一步失败都删除临时资源，不创建数据库记录，不改变当前版本。
- 上传成功后不保留原始 ZIP。
- 系统只做可验证的包结构与安全校验，不承诺从编译产物自动证明 `Avatar151Bridge` 行为兼容。

### 接口与资源访问

- 管理接口提供版本列表、ZIP 上传、元数据编辑、候选预览凭证、启用和删除能力，统一使用现有管理员身份认证。
- 上传接口使用 `multipart/form-data`，包含 ZIP、必填名称和选填备注。
- 编辑接口只允许修改名称和备注。
- 删除接口拒绝删除当前版本与内置版本；成功后同时删除记录和资源目录。
- 启用接口对候选版本执行最终存在性检查，并原子切换当前状态。
- 公开运行配置接口只返回当前启用版本所需的 Loader、Data、Framework、Wasm、StreamingAssets、兜底图、版本标识和桥接对象名。
- 当前运行资源使用不可变、带版本标识的 URL，避免浏览器缓存混用。
- 候选版本资源默认不可公开访问。管理员请求预览时获得仅绑定指定版本、有效期 10 分钟的临时令牌。
- 预览令牌只授予资源读取权限，不授予任何管理操作。
- 资源响应正确设置 Unity WebGL 所需的 `Content-Type`、`Content-Encoding`、缓存和安全响应头。
- 当前版本切换后，已经完成加载的 Unity 实例继续在原页面运行；系统不主动向游客端推送热切换。

### 管理台

- 左侧导航新增独立“数字人形象管理”入口，不占用数据看板空间。
- 页面保持紧凑，包含当前形象卡片、上传按钮和版本列表。
- 上传弹窗包含名称、备注和 ZIP 文件，不增加兼容声明复选框。
- 上传过程显示上传中、校验中、成功或明确失败原因。
- 列表展示名称、状态、内置/上传来源、文件大小、上传人、上传时间、最后修改时间和最近启用时间。
- 每个适用版本提供预览、编辑、设为当前和删除操作；不适用操作禁用或隐藏。
- 预览使用弹窗按候选版本运行 Unity WebGL，并至少显示加载进度、成功状态和失败提示。
- 预览不是启用前置条件。
- 启用和删除均要求二次确认；启用成功后提示“游客端刷新后生效”。
- 页面沿用现有 Ant Design 管理端视觉和响应式规则，不重构其他管理页面。

### 游客端运行时

- 首页和 `/guide` 的大型 Unity 数字人使用运行配置解析器获取当前版本。
- 运行配置解析器优先使用后台当前配置；配置接口失败、配置无效或资源加载失败时回退内置 151 配置。
- 内置 Unity 版本也加载失败时，继续使用现有静态兜底链路。
- 新运行配置继续使用现有 `Avatar151Bridge` 状态、口型和表情消息，不改变问答状态机。
- 游客端页面布局、文案、交互、聊天消息静态头像和其他功能不变。
- 上传包存在 `fallback.png` 时，仅用于对应大型 Unity 形象的加载失败兜底；否则使用现有兜底图。
- 管理员编辑名称和备注不改变运行资源版本，也不触发游客端重新加载。

### 生命周期与留痕

- 上传版本保留到管理员手动删除，不做数量上限和自动清理。
- 当前版本和内置版本不可删除。
- 不提供原始 ZIP 下载、资源导出或跨项目共享。
- 不新增独立审计日志模块；版本记录保留上传人、上传时间、修改时间和最近启用时间。
- 本功能仅服务当前本地项目部署，不引入对象存储、素材中心或多租户概念。

## 测试决策

### 测试原则

- 只测试可观察行为和稳定接口，不断言内部辅助函数、临时目录命名或具体 SQL 实现。
- ZIP 测试使用最小构建夹具，不在测试库中复制真实大型 Unity 包。
- 每个纵向功能必须同时覆盖成功路径、权限拒绝、边界失败和“当前形象不受影响”的回归路径。
- 游客端测试关注实际配置选择、资源 URL、回退结果和页面稳定性，不测试 Unity 内部动画实现细节。

### ZIP 导入器测试

- 接受无包装目录和单层包装目录。
- 接受不同文件前缀。
- 接受未压缩、Gzip 和 Brotli 构建。
- 接受可选 `StreamingAssets` 与 `fallback.png`。
- 拒绝非 ZIP、超出上传大小、超出解压大小、缺少核心文件、多套构建、路径穿越、符号链接、危险文件和损坏压缩包。
- 失败后不存在正式资源目录、数据库记录或当前版本变化。

### 后端接口测试

- 未登录和非管理员无法列表、上传、编辑、预览、启用或删除。
- 初始列表包含内置 151 且只有一个当前版本。
- 上传成功创建候选版本并返回规范化资源清单。
- 名称可重复，编辑只修改名称和备注。
- 当前版本、内置版本不可删除；候选删除后记录和文件均消失。
- 启用操作保持唯一当前版本并记录启用时间。
- 预览令牌仅访问指定版本并在过期后失效。
- 公开配置只暴露当前版本，不泄露候选列表。
- 压缩资源返回正确的媒体类型、内容编码和缓存头。
- 应沿用现有 FastAPI TestClient、临时 SQLite 数据库和管理员登录测试模式。

### 管理台测试

- 导航中出现“数字人形象管理”，路由受管理员登录保护。
- 页面能展示内置当前版本、候选版本和各状态允许的操作。
- 上传、编辑、启用、删除的表单、确认框、成功提示与错误提示正确。
- 预览弹窗加载候选配置，不误用当前运行配置。
- 390px 与桌面视口下无横向溢出，操作仍可达。
- 应沿用现有管理台浏览器验证脚本模式。

### 游客端与回归测试

- 当前为内置版本时，首页和 `/guide` 保持现有效果。
- 启用上传版本后，新加载页面使用新版本化配置。
- 已打开页面不因后台切换而自动销毁或重建 Unity 实例。
- 配置接口失败、候选资源加载失败时回退内置 151；内置 Unity 失败时保留静态兜底。
- 欢迎、空闲、思考、讲解、口型和表情消息继续发送到同一桥接对象。
- 现有游客流程、管理员流程、前端构建和后端测试全部通过。
