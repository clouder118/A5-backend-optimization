# 个性化数字人 PRD

- 状态：已实施并完成专项验收（2026-07-29）
- 任务类型：本地 Markdown
- 产品范围：A5 灵山胜境游客端 `/guide`
- 开发门禁：已由用户解除，PDH-01 至 PDH-04 已完成
- 实施原则：仅实现本文范围，遵循 `karpathy-guidelines`

## 问题陈述

当前 `/guide` 页面中的数字人使用固定的导游身份与“导游模式”配置。游客只能选择儿童版、研学版、长者版及讲解时长，无法根据自己的旅行偏好定义数字人的身份、年龄、性别、性格和表达方式，也无法通过自由文本塑造更鲜活的陪伴角色。

本功能需要用“个性化数字人”替代原有“导游模式”。游客可以通过预设选项快速创建人设，也可以在“创想时刻”中自由描述角色，并选择让 AI 根据快捷选项创作人设或对已有文字进行润色与适当扩写。所有 AI 结果必须先回填到可编辑文本框，由游客主动确认后才保存和应用。

本期只改变数字人的对话身份、措辞和性格表现，不改变现有 3D 模型、“灵诗音”名称、语音音色、固定欢迎语及欢迎音频，也不触碰现有 `/digital-human-settings` 页面。

## 目标

1. 让游客无需编写 Prompt，也能通过常见参数快速创建个性化数字人人设。
2. 为有创作需求的游客提供可选自由文本、AI创作和AI润色能力。
3. 将确认后的人设保存到当前游客账号，并从下一条导游回复开始生效。
4. 保持 `/guide` 现有视觉语言和主流程整洁，不在主界面铺开展示全部参数。
5. 在角色扮演与景区事实之间建立明确边界，避免虚构内容覆盖知识库与安全规则。
6. 完整下线原“导游模式”，避免两套重叠配置同时存在。

## 体验与交互

### 入口

- 删除 `/guide` 聊天标题栏中的原“导游模式”控件。
- 在相同控件区域放置“个性化数字人”按钮，不新增独立路由。
- 点击按钮打开居中的 PC 端弹窗。
- 未保存过配置时显示“个性化数字人”。
- 保存成功后入口以小圆点配合“已个性化”表达状态。
- 主界面不展示身份、年龄、性格、Prompt 等详情。

### 弹窗结构

弹窗按以下顺序排列，内容超过可用高度时只在弹窗内部滚动：

1. 标题与简短说明。
2. 身份分组卡片。
3. 年龄与性别并排区域。
4. 性格与表达风格。
5. “创想时刻”文本框及 AI 操作。
6. 底部操作栏：恢复默认、取消、确认创建。

弹窗沿用 `/guide` 现有暖白底色、轻阴影、细边框、切角按钮、既有字体与间距体系。不得引入另一套视觉主题或修改页面其他区域。

### 身份

身份为必有默认值的单选项，不提供“自定义身份”子选项。

“沉浸式角色”分组：

- 古代书生
- 民国记者
- 未来探险家
- 景区原住民

“旅行陪伴角色”分组：

- 专业导游
- 当地朋友
- 历史文化讲解员
- 美食达人
- 摄影向导
- 旅行管家

同一景点的讲解措辞应随身份变化。例如古代书生偏诗文与典故表达，民国记者偏纪实报道表达，但角色化表达不得改变景区事实。

### 年龄

- 快捷年龄段为：少年、青年、中年、年长、不设定。
- 允许输入 1–120 的具体整数年龄。
- 具体年龄与年龄段使用同一选择逻辑；输入具体年龄后，以具体年龄为实际人设要求，并自动归类显示对应年龄段。
- 非整数、超出范围或不完整输入不得保存。

### 性别

性别为单选：

- 男性
- 女性
- 中性
- 不设定

选择“不设定”时，不向对话 Prompt 注入性别要求。

### 性格

性格允许选择 1–3 项：

- 温柔耐心
- 开朗活泼
- 沉稳专业
- 幽默风趣
- 热情健谈
- 细致体贴
- 好奇博学
- 冷静克制

达到三项后，未选标签不可继续选择；取消已选标签后恢复可选。

### 表达风格

表达风格为单选：

- 简洁直接
- 详细讲解
- 故事化
- 轻松口语
- 正式专业
- 诗意文雅
- 互动提问式
- 不设定

选择“不设定”时，不向对话 Prompt 注入额外表达风格要求。

### 创想时刻

- “创想时刻”是独立的选填区域，不属于身份的子选项。
- 文本框为空时显示占位提示“自由发挥您的创意，详细描述您的奇思妙想”。
- 占位提示不是文本框值，不可被编辑，不计入字符数，也不得随保存提交。
- 游客输入、AI创作和AI润色结果均限制在 1000 个字符以内。
- 文本框右下角显示当前字符数与上限。
- 不填写“创想时刻”也可以确认创建，快捷选项仍能形成完整人设。

### AI帮我创作

- 根据当前身份、年龄、性别、性格和表达风格调用项目现有 LLM。
- 生成约 150–300 字、可直接编辑的人设描述。
- 不虚构具体景区史实，不伪造真实历史人物关系。
- 文本框为空时可直接生成。
- 文本框已有内容时，先询问“将覆盖当前内容，是否继续？”；游客确认后才调用并替换。
- 结果只写回文本框，不自动保存、不自动关闭弹窗、不自动发送消息。
- 请求进行中显示明确加载状态，防止重复调用。

### AI润色

- 仅在文本框存在游客或 AI 文字时可用。
- 保留游客原意和上方已选参数，优化清晰度、细节和表达。
- 允许适当扩写，使角色更鲜活有趣，但结果不得超过 1000 个字符。
- 不擅自改变角色关键设定，不添加游客没有表达的敏感身份信息。
- 结果只写回原文本框，保持可编辑，不自动保存或提交。
- 请求进行中显示明确加载状态，防止重复调用。

### 保存、关闭与恢复

- “确认创建”保存当前配置并覆盖该游客账号的旧配置。
- 保存成功后关闭弹窗，提示保存成功，并更新入口为“已个性化”。
- 新人设从下一条导游回复开始生效；已有消息不修改，也不自动新增消息。
- “取消”、关闭按钮或点击遮罩时，如没有修改则直接关闭。
- 存在未保存修改时，先确认“放弃未保存修改？”。
- “恢复默认”只修改当前弹窗草稿，不立即保存。
- 恢复默认后仍需点击“确认创建”才覆盖账号配置。

## 默认配置

首次打开弹窗时使用以下默认值：

- 身份：专业导游
- 年龄：青年
- 性别：不设定
- 性格：温柔耐心
- 表达风格：不设定
- 创想时刻：空

游客未确认创建前，默认值不作为已保存个性化配置。

## 数据与接口决策

### 持久化

- 每个游客账号最多保存一份当前人设配置。
- 配置与现有 `app_user` 游客账号关联，账号之间严格隔离。
- 再次保存执行覆盖更新，不保留人设版本历史。
- 至少保存身份、年龄模式、年龄段、具体年龄、性别、性格数组、表达风格、创想文本、创建时间和更新时间。
- 文本内容以服务端 1000 字符校验为准，不能只依赖前端限制。
- 本地 SQLite 重启后配置必须保留。

### 游客人设接口

提供受游客登录保护的能力：

- 读取当前账号人设；无记录时返回默认配置和“未个性化”状态。
- 创建或覆盖保存当前账号人设。
- 根据当前表单参数进行 AI 创作。
- 根据当前表单参数与已有文本进行 AI 润色。

所有写入与 AI 接口必须校验登录游客、枚举值、具体年龄、性格数量和文本长度。游客不能读取或修改其他账号的人设。

### LLM 调用

- 复用项目现有 OpenAI-compatible/MiMo 配置与客户端，不新增第二套模型配置。
- AI 创作与润色使用独立、受约束的系统提示词。
- 用户文本只作为待处理人设内容，不得覆盖系统提示词、安全规则与事实约束。
- 调用失败时返回可识别错误；前端统一提示“AI服务暂时不可用，请稍后重试”。
- 失败不得清空或覆盖文本框，也不得改变其他表单选择。
- 不提供本地规则生成降级，不伪装 AI 成功。

## 对话集成

- `/guide` 文字、语音和图片问答均使用当前账号已保存的人设。
- 前端聊天请求不再发送 `guide_mode`。
- 服务端不再解析儿童版、研学版、长者版及半分钟/两分钟配置。
- 服务端将结构化人设转换为受控的人设 Prompt，并放在事实证据与安全规则之下。
- 身份、性格和表达风格可以影响叙事视角、用词、语气和互动方式。
- 景点历史、路线、开放信息、安全提示和其他事实仍遵循现有知识库、检索证据与系统规则。
- “创想时刻”可以描述虚构角色背景，但不得将其包装成真实景区史实。
- 对话缓存键必须包含当前人设的稳定标识，防止不同游客或不同人设命中同一风格答案。
- 保存新配置后，从下一次请求读取新配置；已有聊天记录保持不变。
- 固定欢迎语和欢迎音频不读取人设，不新增页面加载时的自动 LLM 或 TTS 调用。
- 语音音色保持不变，只朗读采用新人设措辞生成的回答。

## 原导游模式下线

本期完整下线原导游模式：

- 删除 `/guide` 标题栏导游模式按钮和选择面板。
- 删除儿童版、研学版、长者版、约半分钟、约两分钟选项。
- 删除 `/guide` 中相关 React 状态、初始化逻辑和 `sessionStorage` 缓存。
- 删除聊天请求中的 `guide_mode`/`guideMode` 参数构造。
- 删除服务端导游模式解析、Prompt、输出长度和缓存分支。
- 删除不再使用的类型、组件、样式和测试断言。
- 清理其他调用点中仅用于传递默认导游模式的代码，但不得改变这些页面的其他行为。
- 历史浏览器中残留的导游模式缓存不迁移，直接忽略。

## 错误与边界行为

- 人设读取失败时，`/guide` 保持可用并使用现有默认回答行为；入口提示加载失败或允许重试，不伪装已保存。
- 保存失败时弹窗保持打开，保留全部草稿。
- AI 请求失败时保留全部草稿和原文本。
- 非法身份、年龄、性别、性格数量、表达风格或超长文本由服务端拒绝。
- AI 返回空文本或超过限制时视为失败，不覆盖原文本。
- AI运行期间禁止重复触发创作或润色；不得出现竞态覆盖。
- 人设配置内容与系统规则冲突时，系统安全、事实和能力边界优先。

## 测试决策

### 后端测试

- 未登录游客不能读取、保存、创作或润色人设。
- 无人设记录时返回规定默认值和未个性化状态。
- 保存后可按当前账号读取并在重启使用同一 SQLite 时保留。
- 第二次保存覆盖第一份配置，不产生多份当前记录。
- 不同游客账号之间配置隔离。
- 身份、年龄、性别、性格数量、表达风格和 1000 字符限制均由服务端验证。
- AI 创作 Prompt 包含当前结构化选择，结果限制为 150–300 字目标且不自动保存。
- AI 润色 Prompt 包含原文和结构化选择，允许适当扩写但保持关键设定，且不自动保存。
- AI客户端异常、空结果和超长结果返回稳定错误，不修改已保存配置。
- 当前人设进入普通文字、流式文字和图片问答 Prompt。
- 语音输入最终走同一文字问答链路并采用当前人设结果。
- 人设 Prompt 不能覆盖事实证据与安全规则。
- 对话答案缓存按人设隔离。
- 旧 `guide_mode` 不再影响 Prompt、长度或缓存。
- 沿用现有 FastAPI TestClient、临时 SQLite 和 LLM monkeypatch 测试方式。

## 验收标准

- [ ] `/guide` 原导游模式完全下线，并由“个性化数字人”入口替代。
- [ ] 游客可以使用规定的身份、年龄、性别、性格和表达风格完成快速个性化。
- [ ] “创想时刻”选填、占位提示正确、最多 1000 字符。
- [ ] AI创作综合结构化选项生成 150–300 字左右的人设文本，并保持可编辑。
- [ ] AI润色保留原意和参数，可适当扩写，并保持可编辑。
- [ ] 两种 AI 操作均不会自动保存、关闭弹窗或发送消息。
- [ ] 覆盖、未保存关闭、恢复默认和 AI 失败行为符合本文约定。
- [ ] 每个游客账号只有一份持久化人设，账号之间互不影响。
- [ ] 保存后入口显示“已个性化”，但主界面不铺展参数。
- [ ] 人设从下一条文字、语音或图片回复开始生效。
- [ ] 角色化表达不改变知识库事实，用户 Prompt 不能覆盖系统规则。
- [ ] 3D 模型、“灵诗音”名称、音色、固定欢迎语和欢迎音频不变。
- [ ] `/digital-human-settings` 不发生修改。
- [ ] PC 端专用验证、前端构建、后端测试与相关回归通过。
