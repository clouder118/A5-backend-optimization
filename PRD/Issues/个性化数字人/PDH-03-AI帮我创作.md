# PDH-03 AI 帮我创作

- 父需求：[个性化数字人 PRD](../../个性化数字人-PRD.md)
- 状态：已完成（2026-07-29）
- 执行类型：AFK（门禁解除后）
- 前置依赖：PDH-02

## 要构建的内容

为“创想时刻”增加“AI帮我创作”能力。系统综合游客当前选择的身份、年龄、性别、性格和表达风格，调用项目现有 OpenAI-compatible/MiMo LLM，生成约 150–300 字的完整人设描述。

生成结果只回填到“创想时刻”文本框并保持可编辑，不自动保存、不自动关闭弹窗、不自动发送聊天消息。文本框已有内容时，必须在调用前确认覆盖。

## 产品行为

- 文本框为空时，点击“AI帮我创作”直接发起生成。
- 文本框已有文字时，先提示“将覆盖当前内容，是否继续？”。
- 游客取消覆盖时，不调用 LLM，不改变文本。
- 生成请求使用当前尚未保存的表单参数，而不是只读取服务端旧配置。
- 目标输出约 150–300 字，内容鲜活但不虚构具体景区史实。
- 成功结果替换文本框内容，保持可编辑，并被视为未保存修改。
- 生成成功不自动执行“确认创建”。
- 请求进行中展示加载状态，禁止重复生成和并发覆盖。
- 调用失败、返回空文本或返回超长文本时，提示“AI服务暂时不可用，请稍后重试”。
- 失败时保留所有结构化选择和原文本。

## LLM 与接口约束

- 复用现有 LLM 配置与客户端，不新增模型供应商或第二套密钥。
- AI创作接口必须要求游客登录并校验全部结构化字段。
- 用户参数作为待生成的人设约束，不能覆盖系统提示词。
- 系统提示词要求输出只包含可编辑的人设描述，不返回 Markdown 标题、解释或提交指令。
- 服务端验证非空结果及 1000 字符硬上限。
- AI创作接口不得直接写入账号人设表。

## 实施边界

- 可以新增独立创作接口和服务函数。
- 可以复用 PDH-02 的人设 Schema，但不得把“生成”和“保存”合并成一次操作。
- 不生成数字人图片、模型、声音、动作或名称。
- 不根据景区实时数据虚构角色经历。
- 不提供多候选结果、历史记录、重新生成次数统计或配额管理界面。
- AI润色由 PDH-04 完成。

## 验收标准

- [ ] 当前快捷选项会完整进入 AI创作请求。
- [ ] 空文本时可以直接生成。
- [ ] 非空文本时必须确认覆盖，取消后不发请求。
- [ ] 成功结果约 150–300 字、非空且不超过 1000 字符。
- [ ] 结果回填原文本框并保持可编辑。
- [ ] 结果不会自动保存、关闭弹窗或发送消息。
- [ ] 保存按钮仍由游客主动点击。
- [ ] 加载期间不会发生重复调用或竞态覆盖。
- [ ] 调用失败、空结果和超长结果均保留原草稿并显示统一错误。
- [ ] 生成内容不伪造具体景区史实。

## 测试要求

### 后端

- [ ] 鉴权、字段校验和账号边界通过。
- [ ] monkeypatch LLM 后可断言系统提示词与结构化参数完整。
- [ ] 成功响应不修改数据库中的已保存人设。
- [ ] LLM异常、空结果和超长结果返回稳定错误。
- [ ] 用户参数无法覆盖系统与事实规则。

### 前端

- [ ] 浏览器验证覆盖空文本生成、非空覆盖确认和取消覆盖。
- [ ] 覆盖加载状态、成功回填、保持可编辑和未自动保存。
- [ ] 覆盖失败时原文和全部选择保持不变。
- [ ] 刷新弹窗前，未点击确认的 AI 结果不会出现在已保存配置中。

### 回归

- [ ] 前端构建和后端相关 pytest 通过。
- [ ] PDH-01、PDH-02 的选择、保存、安全和对话行为保持通过。

## 完成定义

游客可以基于快捷选项一键获得一段可编辑的鲜活人设，并在明确确认前不会丢失已有文字，也不会被系统代替执行保存。
