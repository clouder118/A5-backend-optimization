# PDH-04 AI 润色与适当扩写

- 父需求：[个性化数字人 PRD](../../个性化数字人-PRD.md)
- 状态：已完成（2026-07-29）
- 执行类型：AFK（门禁解除后）
- 前置依赖：PDH-02

## 要构建的内容

为“创想时刻”增加“AI润色”能力。游客输入或生成文字后，可以让项目现有 LLM 在保持原意和关键设定的前提下优化清晰度、细节与表达，并进行适当扩写，使角色更加鲜活有趣。

润色结果只回填到原文本框并保持可编辑，不自动保存、不自动提交、不自动发送消息。任何失败都必须保留原文和表单选择。

## 产品行为

- 文本框为空时，“AI润色”不可用。
- 有文字时，点击按钮以当前文本和全部结构化选项发起润色。
- 润色可以适当扩写，但不得改变身份、年龄、性别、性格或表达风格等关键设定。
- 不添加游客没有表达的敏感身份信息。
- 结果不超过 1000 个字符。
- 成功结果替换原文本，保持可编辑，并被视为未保存修改。
- 润色成功不自动执行“确认创建”。
- 请求进行中显示加载状态，禁止重复调用和竞态覆盖。
- 调用失败、返回空文本或超长文本时，提示“AI服务暂时不可用，请稍后重试”。
- 失败时保留原文本和所有表单选择。

## LLM 与接口约束

- 复用现有 OpenAI-compatible/MiMo 配置与客户端。
- AI润色接口要求游客登录，并校验结构化选项、原文本非空和 1000 字符上限。
- 系统提示词明确要求保持原意、保持关键设定、允许适当扩写、禁止补充敏感身份信息。
- 系统提示词继续强调不得伪造具体景区史实或覆盖系统规则。
- 服务端验证非空结果及 1000 字符硬上限。
- AI润色接口不得直接写入账号人设表。

## 实施边界

- 可以新增独立润色接口和服务函数，也可以与创作接口共享明确的底层 LLM 调用辅助函数。
- 不得把润色和保存合并。
- 不提供文本版本对比、接受部分修改、撤销历史或多候选方案。
- 不对结构化参数本身进行 AI 自动修改。
- 不修改数字人的模型、名称、音色和欢迎内容。

## 验收标准

- [ ] 空文本时无法触发 AI润色。
- [ ] 请求包含当前原文和全部结构化选项。
- [ ] 润色保持原意和关键设定，可适当扩写并使角色更鲜活。
- [ ] 不添加游客没有表达的敏感身份信息。
- [ ] 成功结果非空且不超过 1000 个字符。
- [ ] 结果回填原文本框并保持可编辑。
- [ ] 结果不会自动保存、关闭弹窗或发送消息。
- [ ] 加载期间不会发生重复调用或竞态覆盖。
- [ ] 调用失败、空结果和超长结果均保留原草稿并显示统一错误。
- [ ] 只有游客点击“确认创建”后，润色结果才进入账号配置并影响下一条回复。

## 测试要求

### 后端

- [ ] 未登录、空原文、超长原文和非法结构化参数被拒绝。
- [ ] monkeypatch LLM 后可断言原文、结构化参数和润色约束完整进入提示词。
- [ ] 成功响应不修改数据库中的已保存人设。
- [ ] LLM异常、空结果和超长结果返回稳定错误。
- [ ] 结果规则覆盖保持原意、适当扩写、禁止敏感身份补充和事实优先。

### 前端

- [ ] 浏览器验证空文本禁用、有文本可调用和加载状态。
- [ ] 成功结果回填、保持可编辑且不自动保存。
- [ ] 失败时原文和全部选择保持不变。
- [ ] 未点击确认前，关闭并放弃修改不会污染已保存配置。
- [ ] 点击确认后，下一条文字、语音和图片回复采用润色后人设。

### 回归

- [ ] 前端构建和后端相关 pytest 通过。
- [ ] AI创作、手写 Prompt、结构化快捷配置和旧导游模式下线行为保持通过。

## 完成定义

游客可以将已有创意交给 AI 润色和适当扩写，并始终保有最终编辑与提交权；AI不会静默改变关键设定，也不会在失败时破坏原文。
