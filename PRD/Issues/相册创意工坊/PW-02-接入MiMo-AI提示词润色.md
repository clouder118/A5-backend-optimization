## What to build

在创作区增加完整的 AI 提示词润色链路。游客只需输入非空文字即可调用润色，尚未上传参考图也允许使用。后端通过专用配置调用 `mimo-v2.5-pro`，不得改变数字人聊天正在使用的模型或温度等配置。

润色规则将游客原意组织为自然、清晰、具体的图片编辑提示词，覆盖主体、动作、环境、风格、色彩、光影、构图、用途、图中文字和“需要修改/保持不变”的边界。允许适度扩写，但不得改变核心意图或加入无关主体。

润色期间只在按钮内显示加载状态；成功结果覆盖原输入框并继续可编辑，不自动触发图片生成。失败时保留原文并显示脱敏错误。

## Acceptance criteria

- [x] 非空提示词在没有参考图时也可以调用 AI 润色。
- [x] 空提示词不能调用润色，并获得明确输入提示。
- [x] 润色使用 `mimo-v2.5-pro` 和专用功能配置，不改变数字人对话模型。
- [x] MiMo API Key 只由后端读取，不进入浏览器、响应、日志或提交。
- [x] 润色规则包含主体、动作、环境以及按需的风格、色彩、光影和构图。
- [x] 润色规则要求明确应用场景、精准风格词和参考图作用。
- [x] 需要渲染的图片文字使用双引号表达。
- [x] 图片编辑指令明确修改对象、操作和必须保持不变的部分。
- [x] 润色允许适度扩写，但不会擅自改变游客核心意图。
- [x] 润色过程中只显示按钮加载状态，不显示 Lightfall，也不允许重复点击。
- [x] 润色成功后覆盖当前输入框、保持可编辑且不自动生成图片。
- [x] 润色结果同样遵守 2000 字上限，异常超长结果得到可理解处理。
- [x] 润色失败时保留原文，并且错误信息不泄露 Key、上游响应或堆栈。
- [x] 后端测试使用假 MiMo 客户端覆盖请求规则、成功、空响应、超长、超时和拒绝。
- [x] 前端测试覆盖未上传图片时润色、按钮加载、成功覆盖、失败保留和不自动生成。
