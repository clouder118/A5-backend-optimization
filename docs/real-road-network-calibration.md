# 双景区人工步行路网说明

## 当前数据

- `knowledge/routes/ling-shan-road-network-v1.json`
- `knowledge/routes/nianhua-bay-road-network-v1.json`
- `knowledge/routes/road-time-anchors-v1.json`

路网只保存道路节点和人工描绘的折线。所有道路统一视为普通、双向、可步行道路，不再维护难度、道路类型、无障碍状态或景点入口绑定。

景点位置会自动吸附到同一张地图中最近的道路节点。经过其他景点附近只代表道路经过，不会把该景点自动加入游览顺序。

## 标注与导出

启动前端后打开：

`/tools/scenic-map-calibrator.html`

操作顺序：

1. 选择景区地图。
2. 在“景点点位”中校正景点的大概位置。
3. 在“道路描绘”中按住鼠标沿游客可走道路滑动。
4. 在岔路口结束当前道路，再从同一节点继续描绘。
5. 删除错误道路后，可使用“清理孤立节点”移除残留白点。
6. 在“时间标定”中录入少量已知步行时间。
7. 确认路网检查通过后复制路网 JSON。

工具导出的道路只含：

- `id`
- `from_node_id`
- `to_node_id`
- `points`

## 时间估算

折线长度按原图像素计算，只用于同一地图中的相对时间，不显示为现实米数。

当前粗略参考：

- 灵山：佛足坛到灵山大佛约 25 分钟。
- 拈花湾：拈花广场到梵天花海约 10 分钟。

每张地图分别根据自己的参考时间计算“分钟/地图像素”系数。当前结果统一标记为“地图估算”，只提供大概游览时间。

## 寻路

后端使用 Dijkstra 算法按道路折线长度寻找最短路径。旧客户端仍可传 `fastest`、`easy` 或 `accessible`，但为保持兼容，三者目前都会使用同一套普通道路最短路径计算。

`POST /api/maps/{map_id}/route-path` 会返回道路折线、粗略分钟数和缺失路段。灵山与拈花湾的路网完全隔离，不能跨地图寻路。
