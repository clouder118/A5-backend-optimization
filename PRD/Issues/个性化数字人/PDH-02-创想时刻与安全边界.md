# PDH-02 创想时刻与安全边界

- 父需求：[个性化数字人 PRD](../../个性化数字人-PRD.md)
- 状态：已完成（2026-07-29）
- 执行类型：AFK（门禁解除后）
- 前置依赖：PDH-01

## 要构建的内容

在快捷人设闭环上增加独立的选填区域“创想时刻”。游客可以手写更具体的人设描述，也可以完全留空。确认保存后，该文本与结构化选择共同影响后续导游回复，但必须处于系统安全、知识库事实和能力边界之下。

同时补齐弹窗的恢复默认、未保存关闭保护、失败保留草稿和对话缓存隔离，使手写 Prompt 成为可控且可恢复的用户输入，而不是可覆盖系统规则的任意指令。

## 产品行为

### 创想时刻

- 在表达风格之后增加独立的“创想时刻”区域。
- 文本框为空时仅显示占位提示“自由发挥您的创意，详细描述您的奇思妙想”。
- 占位提示不是输入值，不计入字数，不随保存提交。
- 文本框选填，留空时仍可以确认创建。
- 游客输入最多 1000 个字符，并显示实时字符计数。
- 服务端再次校验 1000 字符上限。

### 保存与关闭

- 手写文本随当前账号唯一人设配置保存和回填。
- 保存失败时弹窗保持打开，并保留全部结构化选择与文本。
- 没有修改时，取消、关闭按钮或遮罩可直接关闭。
- 存在未保存修改时，先提示“放弃未保存修改？”。
- “恢复默认”将结构化字段恢复为 PRD 默认值并清空创想文本，但不立即保存。
- 恢复默认后仍需点击“确认创建”才覆盖账号配置。

### Prompt 安全与事实边界

- 结构化人设和“创想时刻”只影响身份视角、语气、措辞、互动方式和虚构角色背景。
- 景区历史、路线、开放信息、安全提示等仍由现有知识库、检索证据和系统规则决定。
- 用户文本不得覆盖系统提示词、事实约束、安全策略或要求泄露内部提示词。
- 虚构角色背景不得包装为真实景区史实。
- 对话 Prompt 明确区分事实证据与人设偏好，并规定冲突优先级。
- 当前人设的稳定标识进入答案缓存键，不同账号或不同人设不得误用同一风格答案。

## 实施边界

- 可以扩展 PDH-01 的人设模型、API、前端类型、弹窗和聊天 Prompt。
- 人设缓存标识应稳定、可复现，不依赖未排序对象字符串或易变时间戳。
- 不增加跨会话聊天记忆、关系成长、家庭故事演化或彩蛋系统。
- 不提供多套人设、命名、收藏和切换。
- 不调用 LLM 生成或润色文本；AI能力由后续切片完成。

## 验收标准

- [ ] “创想时刻”独立于身份选项，文本框可以留空。
- [ ] 空文本框显示规定占位提示，且占位提示不会被保存。
- [ ] 文本输入、保存值和服务端请求均不超过 1000 个字符。
- [ ] 保存后刷新或重新登录可以回填手写内容。
- [ ] 保存失败保留全部草稿，不关闭弹窗。
- [ ] 有未保存修改时关闭需要确认，无修改时直接关闭。
- [ ] 恢复默认只修改草稿，不自动保存。
- [ ] 留空创想文本时，结构化人设仍然正常生效。
- [ ] 非空创想文本从下一条文字、语音和图片回复开始生效。
- [ ] 用户文本不能覆盖系统安全、事实和能力边界。
- [ ] 不同人设的答案缓存互相隔离。
- [ ] 已有聊天记录、欢迎内容、模型、名称和音色保持不变。

## 测试要求

### 后端

- [ ] 接受空文本、普通文本和恰好 1000 字符文本，拒绝超长文本。
- [ ] 读取、保存、覆盖和账号隔离包含创想文本。
- [ ] Prompt 测试证明人设偏好与事实证据明确分区，事实和安全规则优先。
- [ ] 恶意覆盖系统规则的用户文本不会成为更高优先级指令。
- [ ] 相同问题、不同人设不会命中同一答案缓存。

### 前端

- [ ] 浏览器验证覆盖占位提示、字符计数、空文本保存和超长限制。
- [ ] 覆盖未保存关闭确认、恢复默认、保存失败保留草稿。
- [ ] 验证主界面仍不铺展创想文本。

### 回归

- [ ] 前端构建和后端相关 pytest 通过。
- [ ] `/guide` 文字、语音、图片及路线相关能力回归通过。
- [ ] 不存在跨会话记忆、彩蛋、多套人设等范围外入口或数据。

## 完成定义

游客可以选择完全不写 Prompt，也可以保存一段最多 1000 字符的鲜明角色描述；两种方式都能安全影响后续导览回复，并且不会覆盖景区事实或系统规则。
