## DH-01 建立内置数字人版本与管理台只读总览

### 父需求

[数字人形象管理 PRD](./数字人形象管理-PRD.md)

### 要构建的内容

建立数字人版本的最小领域模型和读取链路，将项目现有 151 数字人登记为不可删除的内置当前版本。在管理台新增独立“数字人形象管理”导航和页面，端到端展示当前形象卡片与版本列表。

本切片只提供只读能力，不包含上传、编辑、预览、启用或删除。完成后，管理员可以从明确入口看到系统已有且正在运行的数字人版本，其他游客端和管理端功能保持不变。

### 验收标准

- [ ] 管理员登录后可从独立导航进入“数字人形象管理”页面。
- [ ] 页面显示内置 151 数字人的名称、内置标记和“当前使用”状态。
- [ ] 初始状态恰好有一个当前版本。
- [ ] 内置版本记录不可删除，并保留现有资源位置，不搬迁大型资源。
- [ ] 版本列表接口仅允许管理员访问。
- [ ] SQLite 只保存数字人元数据，不保存 Unity 二进制内容。
- [ ] 页面沿用现有 Ant Design 管理端风格，在移动端和桌面端无横向溢出。
- [ ] 后端接口测试、管理端浏览器验证和现有管理端回归通过。

### 前置依赖

无，可以立即开始。

## DH-02 端到端导入 Unity WebGL ZIP 候选版本

### 父需求

[数字人形象管理 PRD](./数字人形象管理-PRD.md)

### 要构建的内容

在管理页面加入上传弹窗，通过管理员鉴权接口接收名称、备注和 Unity WebGL ZIP。建立独立 ZIP 导入器，安全识别唯一构建、校验大小和内容、解压到临时目录，并在全部成功后保存本地资源和候选版本记录。

导入器兼容常见 Unity 导出包装目录、不同文件前缀、未压缩/Gzip/Brotli 核心构建、可选 `StreamingAssets` 和可选 `fallback.png`。任何失败都必须清理临时内容，不改变当前版本。完成后，新候选版本立即出现在管理列表中，但不会影响游客端。

### 验收标准

- [ ] 管理员可以填写必填名称、选填备注并上传一个 ZIP。
- [ ] ZIP 上传上限为 100 MB，解压总量上限为 300 MB。
- [ ] 支持无包装目录或单层包装目录中的唯一 `Build`。
- [ ] 支持一组不同前缀的 Loader、Data、Framework 和 Wasm 核心文件。
- [ ] 支持未压缩、`.gz` 和 `.br` 构建，以及可选 `StreamingAssets`、`fallback.png`。
- [ ] 拒绝非 ZIP、损坏包、缺失核心文件、多套构建、路径穿越、符号链接、ZIP 炸弹、嵌套归档和危险文件。
- [ ] 解压先发生在临时目录，校验成功后才进入不可变版本目录并写入数据库。
- [ ] 导入失败后没有候选记录、正式资源目录或当前状态变化。
- [ ] 导入成功后不保留原始 ZIP，候选列表显示名称、备注、大小、上传人和上传时间。
- [ ] 相同名称可以重复上传，并产生不同版本 ID。
- [ ] 未登录或非管理员上传请求被拒绝。
- [ ] 管理页面清楚显示上传中、校验中、成功和具体失败信息。
- [ ] ZIP 导入器单元测试、上传接口集成测试和管理端上传浏览器验证通过。

### 前置依赖

- DH-01

## DH-03 编辑和删除本地候选版本

### 父需求

[数字人形象管理 PRD](./数字人形象管理-PRD.md)

### 要构建的内容

为版本列表增加元数据编辑和本地资源删除能力。管理员可以修改已上传版本的名称与备注，修改不会改变资源版本或游客端运行状态。管理员可以经过确认删除未启用候选版本，系统同步删除数据库记录和对应本地资源。

内置版本与当前启用版本始终不可删除。系统不自动清理历史版本，不提供原始 ZIP 下载或资源导出。

### 验收标准

- [ ] 管理员可以编辑上传版本的名称和备注。
- [ ] 文件、版本 ID、上传时间、上传人和状态不可通过编辑接口修改。
- [ ] 编辑成功后更新最后修改时间，但不改变当前版本或游客端资源地址。
- [ ] 名称不要求唯一，空名称被拒绝。
- [ ] 管理员可在二次确认后删除未启用候选版本。
- [ ] 删除成功后数据库记录和版本资源目录均不存在。
- [ ] 当前启用版本和内置版本的删除请求被明确拒绝且资源保持完整。
- [ ] 文件删除失败时不得留下数据库已删除、资源仍残留的无提示不一致状态。
- [ ] 未登录或非管理员不能编辑或删除。
- [ ] 页面正确禁用或隐藏不适用操作，并展示成功与失败反馈。
- [ ] 接口集成测试和管理端编辑、删除浏览器验证通过。

### 前置依赖

- DH-02

## DH-04 使用临时令牌预览候选 Unity WebGL 形象

### 父需求

[数字人形象管理 PRD](./数字人形象管理-PRD.md)

### 要构建的内容

为任意候选版本提供管理员触发的预览弹窗。管理员点击预览后获得仅绑定该版本、有效期 10 分钟的临时读取令牌，弹窗通过候选版本自身的 Loader、Data、Framework、Wasm、可选 StreamingAssets 和兜底图启动 Unity。

资源服务必须为未压缩、Gzip 和 Brotli 文件返回正确媒体类型、内容编码和缓存策略。预览展示加载进度、成功或失败状态，不修改当前版本，也不作为启用的强制前置条件。

### 验收标准

- [ ] 管理员可以为指定候选版本申请有效期 10 分钟的预览令牌。
- [ ] 令牌只允许读取指定版本的预览资源，不能访问其他候选版本或调用管理操作。
- [ ] 无令牌、错误令牌、跨版本令牌和过期令牌均被拒绝。
- [ ] 预览弹窗使用候选版本配置，不误用当前运行版本。
- [ ] 弹窗展示 Unity 加载进度、加载成功状态和明确失败提示。
- [ ] 关闭弹窗时释放 Unity 实例、脚本和画布资源。
- [ ] 未压缩、Gzip、Brotli 资源返回正确的 `Content-Type` 与 `Content-Encoding`。
- [ ] 可选 StreamingAssets 和 `fallback.png` 能通过同一令牌访问。
- [ ] 预览成功或失败均不改变当前版本状态。
- [ ] 候选版本未预览也不会被系统标记为不可启用。
- [ ] 预览令牌、资源权限、响应头接口测试和管理端预览浏览器验证通过。

### 前置依赖

- DH-02

## DH-05 启用新版本并让游客端安全加载与回退

### 父需求

[数字人形象管理 PRD](./数字人形象管理-PRD.md)

### 要构建的内容

打通管理员启用到游客端运行的完整路径。管理员确认后将候选版本原子切换为唯一当前版本；游客端运行配置接口只返回当前版本所需的版本化资源地址和桥接信息。新打开或刷新的首页、`/guide` 使用该配置，已打开页面不接收热切换。

数字人加载逻辑保持现有页面结构和 `Avatar151Bridge` 状态交互不变。配置读取、上传资源或 Unity 运行失败时自动回退内置 151；内置 Unity 也失败时继续使用现有静态兜底。管理员可将内置版本重新设为当前。

### 验收标准

- [ ] 管理员点击“设为当前”时看到二次确认，成功后提示游客端刷新生效。
- [ ] 启用操作在事务中保持恰好一个当前版本，并记录最近启用时间。
- [ ] 启用前再次确认候选记录和核心资源存在；失败时原当前版本保持不变。
- [ ] 管理员可以将内置 151 重新设为当前。
- [ ] 公开运行配置只返回当前版本，不包含候选列表或管理信息。
- [ ] 运行配置包含 Loader、Data、Framework、Wasm、可选 StreamingAssets、兜底图、版本标识和桥接对象名。
- [ ] 资源 URL 不可变且带版本标识，切换后不会误用浏览器旧缓存。
- [ ] 新打开或刷新的首页和 `/guide` 使用最新当前版本。
- [ ] 已打开游客页面不会因后台切换而主动销毁或重载当前 Unity 实例。
- [ ] 欢迎、空闲、思考、讲解、口型和表情状态继续发送至既有桥接接口。
- [ ] 游客端布局、文案、问答交互和聊天静态头像没有变化。
- [ ] 当前配置接口失败、配置无效或上传版本加载失败时使用内置 151。
- [ ] 内置 Unity 加载失败时继续使用现有静态兜底。
- [ ] 编辑名称和备注不会改变资源版本或触发游客端重新加载。
- [ ] 当前版本资源访问受控，游客不能枚举或读取未启用候选版本。
- [ ] 运行配置接口测试、游客端浏览器验证、后端完整测试、前端构建和现有游客/管理端回归全部通过。

### 前置依赖

- DH-01
- DH-02

## 建议实施顺序

1. DH-01：先建立可见、可测试的内置版本读取闭环。
2. DH-02：加入安全导入和候选版本闭环。
3. DH-03 与 DH-04：可在 DH-02 完成后并行实施。
4. DH-05：最后接入启用和游客端运行配置，完成真实替换闭环。

该拆分保持每项任务均可独立演示和验收，同时避免把数据库、接口、管理页面或游客端分别拆成无法单独交付的水平任务。
