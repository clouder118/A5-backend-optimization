# 单路线个性化推荐引擎

## 请求契约

`POST /api/routes/recommend` 使用四项核心偏好：

- `map_id`：`ling-shan` 或 `nianhua-bay`
- `duration_minutes`：游览预算
- `physical_level`：`low`、`medium`、`high`
- `interest_tags`：最多两个主题

支持的主题为：佛教文化、建筑艺术、演艺亲子、摄影打卡、自然休闲、室内体验。

`visitor_type` 为可选兼容字段。只有在没有提供兴趣主题时，旧游客类型才会转换为默认主题。响应继续使用 `items` 数组，但只返回一条路线。

## 推荐数据

景点详情标签不再直接决定推荐分数。推荐引擎读取版本化的 `SpotRecommendationProfile`：

- 六类主题各自的 0–3 分
- 景点基础重要度
- 最短停留时间
- 建议停留时间
- 数据版本

入口只作为路线起点，不参与个性评分。

## 路线生成

- 从当前景区入口出发，不要求返回入口。
- 使用人工路网计算景点间步行时间和道路边。
- 景点不得重复。
- 低、中、高体力的步行上限分别为预算的 25%、40%、55%。
- 重复道路不得超过约 5 分钟，同时不得超过总步行长度的 10%。
- 采用宽度 600 的有界搜索，并按“已访问集合＋当前位置”做支配剪枝。
- 60、90、120、180 分钟分别最多选择 3、4、6、8 个正式景点。

搜索先使用最短停留时间。选出路线后，再以 5 分钟为单位将剩余预算优先分配给主题匹配度和重要度更高的景点，但不超过建议停留时间。

## 降级规则

- 路网可用但常规搜索无结果时，返回入口加一个预算内可达的最高分景点。
- 路网不可用时，只返回当前景区最匹配的一条人工模板。
- 不跨景区混合景点，不使用直线补齐缺失道路。
- 相同输入和相同数据版本返回稳定结果。
